# Mixed writer validation — prepared source

No runtime qualification has been performed for this source. This isolated phase
is not collected by the ordinary repository test configuration.

M01 runs one actual mixed NodeClient, qualified WebSocket and SQLite worker. Real
authenticated routes dispatch an assistant answer, the first contribution of a
two-participant discussion, an allocated task, then an ordinary task. Each has
one actual canonical CLI/guardian pair. The discussion is cancelled through its
real route after that contribution; no full synthesis or accepted plan is claimed.
Only the allocated run may create managed outbox rows or physical journal receipts.

M02 starts one ordinary and one allocated task, checks identical/changed starts,
closes the actual runner and journal worker, then opens the same namespace with a
new incarnation. Old ordinary starts and both mode changes must reject without a
new producer or filesystem content change. Genuine DB-owned resume dispatch
rejects the unknown ordinary producer without claiming physical absence, and
reports the fully delivered managed run as `process_exited` without respawning.
Pending closed delivery is independently covered by existing W11. A fresh
ordinary task then executes once. This is same-OS-process
reopening, not full daemon crash/restart or old-producer adoption evidence.

The receipt receiver and HTTP business/auth/device routes are real production
code over the existing PGlite test server. External OIDC and provider answers are
explicit local fixtures. Negative command injection uses the already authenticated
owned proxy socket; it never synthesizes receipts or physical authority. Original
and injected command bytes, hashes, actual rejection ACKs and before/after
workspace/producer inventories are retained. No server rows are hand-seeded to
bypass routes. Existing physical/network helpers are imported without edits.

Run only after root releases the serialized runtime slot and freezes this entire
checkout and its dependencies:

```sh
nice -n 10 python3 validation/managed-workspaces/mixed/run.py --execute
```

The wrapper imports the existing managed validation orchestrator and
`support.owned_phase`. It takes the same checkout lock, verifies Node 24.19.0 and
nice 10 on macOS, forces the complete repository TypeScript build, runs the
dedicated noEmit check, and runs exactly the two listed titles with one worker.
Build and typecheck each have 600 seconds; tests have 240 seconds; each command
has the unchanged 10-second owned cleanup budget. Tests retain 90-second cases
and 20-second hooks. There is no install, retry or automatic next phase.

The complete source inventory covers these harness source files and reused
fixtures; runtime inventories cover compiled products, dependencies and tools.
There is no generated harness bundle. All product imports use the same compiled
repository graph, with the real child-process observation mock delegating every
spawn to the built-in API. This preserves canonical producer WeakMap authority.

Each attempt writes `report.html`, including failures before a case starts.
`photos=[]` explicitly means zero GUI photos. This backend/worker slice does not
qualify installed Mac/iOS UI, real providers, independent production PostgreSQL,
signing/notarization or commercial readiness.

## Retained evidence schema

`tests/mixed-observations.json` has `schema_version: 1`, `photos: []` and an
`observations` array:

- `mixed-run`: exact original wire text and SHA-256 plus parsed command, actual child program
  entry and context hash, two per-run CLI/guardian physical observations, durable
  journal row, server run, authenticated ingest receipts and events.
- `mixed-fixture-cleanup`: ownership root, expected count, actual launch records,
  spawn/exit/stdio/group-absence lifetimes, per-run physical observations, selected
  commands, journal incarnations, runner/connection counts, real HTTP/wire history,
  retained injection records and read-only final outbox/receipt rows. `removed`,
  `journalClosed`, `sourceUnchanged`, failures and dispatcher errors are explicit.
- `mixed-reopen`: old/new journal incarnations, ordinary/managed/fresh run IDs and
  actual before/after launch and storage inventories.
- `M01` / `M02`: final body-plus-owned-cleanup result. Setup failures instead keep
  `mixed-fixture-setup-failure` with acquired-resource cleanup observations.

Qualification expects 2 fixtures, 7 actual program entries, 7 CLI/guardian pairs,
7 per-run observations and 8 labelled injected commands (1 duplicate acceptance,
7 rejections). These are requirements, not prefilled observed counts. Every
observed Git/CLI/guardian must close. Failed/uncertain fixture directories and
their ownership markers are retained; parent removal requires all actual checks
plus full input stability and outer owned closure to pass.
