# Artoo UI 与调度重构联合实施计划

日期：2026-11-16。状态：已启动并行实施，整体验证待全部代码集成后执行。

## 产品重心校正：多电脑、多 Agent 协同

用户明确平台重点是多台电脑上的多个 Agent 协作完成一个项目。
当前先交付这条核心流程，所有后台和 UI 改动都围绕它排序：

> 多台电脑接入 → 发现各机 Agent/能力 → 为项目配置团队与角色 →
> 围绕同一 Goal 讨论并形成计划 → 人工接受 → 独立任务并行、依赖任务有序执行 →
> 共享必要上下文、传递可核验产物、提问/阻塞/评审 → 汇总结果由用户验收。

协作的验收不能只看多个独立任务同时运行。至少包含两台真实电脑、两个真实 Agent：
互不依赖的任务在隔离目录并行；一个下游任务等待上游完成和产物通过原有验收，
再取得与上游版本绑定且可访问的输入；另一个 Agent 能提出评审意见并完成返修闭环。
界面必须回答“谁在哪台电脑做什么、依赖谁、交给谁、被什么阻塞”。
聊天记录或交接 metadata 本身不证明文件已交付，人工接受也不冒充 Agent 独立评审。

- 当前优先：T02/T04/T05 的协作可见性、T03/T07 的逻辑团队、T10/T11 的真实领取执行、
  T12/T13 的恢复与并发隔离，以及 Windows 上核心真实执行所必需的组合支持。
- 继续保留：一次执行授权、节点拥有的验证、真实进程停止、租户范围和旧手工路径。
  这些是多机协作可靠运行的条件。
- 核心闭环之后：T15 新增发布目标、T17 新增 Provider、非必要的平台扩展与 T20 长期退出安排。
  原 21 个任务包仍保留跟踪；后置不计作已完成，不用外围功能替代核心协作验收。
- 完全排除：电脑开机、关机、重启、唤醒和电源管理。

截至本次范围校正，T01、T02a、T08、T09、T10 的首批实现已分别通过
PR #161–#165 合入 main，均待最终统一验证；这不表示真实多机协作已验收。

“暂停接收新任务”不关闭电脑或停止已有 Run。任务 Stop 仅停止对应任务的执行进程。

本计划将已交付的 UI 设计与 [Cowork 调度重构](cowork-scheduler-refactor.md)

## 2. 最快交付策略

采用 **三条开发线 + 一条集成测试线**，先交付新 UI 下的现有真实流程，
并行补齐新调度执行、资源管理与发布能力。集成测试从第一批改动开始，
最终仍在全部实现后的同一最新 main 版本统一运行完整测试与 E2E。

第一条业务闭环为：

> 真实登录 → 配对机器 → 配置 Agent/Squad → 创建需求 → 审核计划 →
> 入队与执行 → 查看真实事件/提问 → 人工评审或返修 → 在已配置目标上发布。

现有手工任务路径用于第一批可用交付，新自动调度路径在资格完整后接入同一 UI。
未完成的能力显示服务端给出的不可用原因，已实现功能正常可用。

为了加快实现，建议把原有全局串行开发调整为**独立工作树并行开发、main 串行合并**：
每项开始时从 fetch 后的最新 main 建分支；合并前再次同步最新 main，重跑受影响检查；
一次合入一项，通过后下一项重新同步。各任务不依赖未合并分支，不在旧基线上堆叠 PR。
该并行布置现已获用户授权并启动；验证时机遵循本文顶部最新执行约定。

## 4. 先固定的对接规则

1. **保留服务端状态机。** UI 六栏是显示投影。真实 Task 仍有 backlog、ready、
   assigned、running、awaiting_approval、blocked、review、done、cancelled；
   失败尝试保留为 Run 历史。审批、阻塞、取消与旧失败不可被六栏折叠后隐藏。
   Task 优先级保留现有四级，不照抄原型三级整数。
2. **前端使用真实查询与命令。** 复用 ApiClient、React Query、RealtimeProvider、
   游标恢复、幂等键与版本冲突处理。新增页面 ViewModel，不引入第二个可写的全量 World。
   计划、取消、重试、评审、发布在服务器成功持久化后才显示成功。
3. **Agent 与实例分层。** Agent 是逻辑身份/角色，实例是其机器、Runtime 和本地工作区。
   Squad 的逻辑 Agent 关系与旧实例 project scope 显式兼容；不凭旧绑定推断新的任意机器授权。
   说明文本进入受约束的上下文，不成为远程 argv、受保护验证命令或节点凭证。
4. **机器能力来自节点。** UI 不直接修改“已安装 CLI”、在线状态或真实硬件；
   标签和容量是独立管理配置。排空只停止新准入，保留活跃运行与资源占用。
   不移植原型的断电按钮，不增加主机电源 API；任务进程停止与节点接单设置分别展示。
5. **授权作用域明确。** 现有 `scheduler.attempt-renew.v1` 仅用于续租，
   不扩充为结果/事件/Stop 的隐式权限。新增生命周期权限单独版本化，保持原用户授权、
   机器/项目/Run/epoch/会话绑定与节点拥有的验证证据。
6. **错误与不确定性可见。** 租约过期、逻辑 cancelled、CLI exit、模型回答与
   物理进程树确认退出是不同事实。停止、接管、清理不得跳过真实闭合确认。
   自动重试/故障转移需要明确、有界的新授权，不能复用一次执行授权无限重试。
7. **复用设计与现有工程。** 保留 React/Vite/npm workspace；移植可复用 JSX、
   组件及视觉变量。为原型大量 utility 类使用限定扫描/作用域的 Tailwind 4 样式入口，
   不引入全局 Preflight 覆盖现有页面。不复制原型的包管理锁文件、Figma 插件和 Vite 配置；
   图标先映射到现有依赖。T01 验证构建、样式隔离和包体影响后固定实现方式。
8. **保留既有使用方式。** 手工 Goal、Channels、Skills、Memory、Settings、
   深链接、桌面 HashRouter 与 iOS/API 兼容继续可用。移动端导航、双栏折叠、
   抽屉焦点、键盘与发送按钮可达性纳入移植验收。
9. **成本要求不变。** 精确计量要求保留，费用预算继续关闭；未知费用不能伪装成零或估算硬上限。

## 8. 验收安排

每项合并前执行与变动相称的聚焦测试、类型检查与构建；JS/TS/JSON/CSS 按
`AGENTS.md` stage 指定文件，`npm run check:staged`，格式化后重新 stage。
UI 操作从 M1 就做真实浏览器冒烟与服务端持久化读回；不等所有页面完成才发现接口不通。

T19 在同一冻结 main SHA 上至少执行：

```powershell
npm run typecheck
npm run build
npm test -- --maxWorkers=2
npm run test:e2e --workspace @artoo/web
npm run test:e2e:scheduler --workspace @artoo/web
npm run test:e2e:capacity --workspace @artoo/web
```

还要按改动范围完成 PostgreSQL 独立连接并发、受保护 journal 原生测试、
POSIX verification subprocess、桌面 Web 壳/相关原生 API 兼容，以及真实 Provider、
双机故障、发布与恢复演练。涉及 storage timeout/cleanup 时执行项目要求的独立父夹具，
保留其刻意失败子用例的证据，不能把子用例失败掩盖为普通集成通过。

业务检查覆盖：

- 登录/注销/换账号后的项目隔离；配对失败/过期/撤销与真实 Runtime 发现。
- Agent/Squad 配置、机器排空、三层容量，以及无资格/缺 Runtime/未知配置的明确提示。
- 规划、编辑、接受、单次入队/去重、树深度/数量与 DAG 约束；未接受/未授权不执行。
- 准备/执行区分、取消/启动竞态、自动续租、提问回复、节点拥有的验证与真实进程闭合。
- 人工评审、返修、真实差异与不可变产物；旧 epoch/跨机器/跨项目/旧会话写拒绝。
- 刷新、多客户端与断网恢复后不重启重复任务、不丢消息、进度不倒退或伪造完成。
- 两个真实隔离 Run、两台机器故障转移、实际退出前目录保留与失败恢复。
- 发布授权、目标配置、合并后测试、实际产物/发布/健康失败/恢复及审计读回。
- 深浅主题、窄屏与桌面壳；保持现有 Channels/Skills/Memory/Settings 与手工 Goal 可用。

不反复索取密钥。先做可独立完成的开发和受控集成；真实验收使用经过核验的本地配置与授权。
