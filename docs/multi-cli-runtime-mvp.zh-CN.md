# Artoo 多 CLI 接入 MVP：让一台节点上的新 CLI 真正接单

状态：提案，2026-11-18。本文是 T17 的首个可交付切片，不代表适配已实现或已通过真机验收。

## 一、用户能做什么

打开「计算机 → 运行时」，看到这台电脑有哪些编码 CLI、哪些能派单、不能用的原因。用户选定 Copilot，贴一段 diff，让它总结改动或建议测试；页面逐步显示回答，可以中途停止。只处理任务提供的文本，不把仓库或终端交给模型。

| 范围 | 首版决定 |
| --- | --- |
| 不变 | Codex、Claude Code 的注册、手动任务和已有能力不变，不迁移到新协议。 |
| 新增发现 | GitHub Copilot CLI、Antigravity CLI（`agy`）、Gemini CLI（`gemini`）、OpenCode、Cursor CLI。两种 Google CLI 是独立条目；遇到同名通用命令不凭文件名认定产品。 |
| 必须可执行 | Windows x64、一台在线节点、一个真实 Copilot 账号、手动单轮无工具任务。**至少 Copilot 真机验收通过才算 MVP 完成**，仅做出清单是中间成果。 |
| 第二候选 | `agy` 独立通过相同验收才开放；不通过只展示发现结果，不阻塞 Copilot，也不把它算作旧 Gemini 的适配。 |
| 不做 | 自动安装/登录、自动选模型、多轮续聊、读写真实项目、Shell、外接 MCP、自动调度、自动评审或发布。其余 CLI 和更多平台的执行资格留到下一版。Multica、Slock/Raft 只作产品对标，不作运行依赖。 |

## 二、从发现到派单

1. **发现不花模型额度。** 配对、启动或手动刷新时，仅按内置清单找候选；普通心跳不启动 CLI。不要运行未确认身份的脚本，不接受服务端下发的命令或参数。可信入口才可做限时版本探测；无法识别的 Windows shim 显示「入口未确认」，不回退到 shell。路径、账号、原始日志留在本机。
2. **验证要由节点操作员触发。** 选择「验证连接」前提示会向 Provider 发送一条固定、不含项目数据的请求，可能产生费用。只有明确的认证失败才提示「请在本机登录」；网络故障、额度不足、状态未知分别展示。验证成功不等于授予读写代码的权限。
3. **页面给出下一步。** `Copilot · 已就绪 · 仅手动单轮` →「发起任务」；`Antigravity · 已安装，未验证` →「验证连接」（有适配器时）；`OpenCode · 已安装，暂不支持执行` → 无派单按钮。旧节点没有清单时显示「未上报」，不误报成「未安装」。节点离线或资格失效时不再可选。

## 三、三步交付

| 步骤 | 实现位置及决定 | 交付门槛 |
| --- | --- | --- |
| M1：看得到 | `scripts/npm-daemon/local-config.mjs` 与 `apps/artood/src/main.ts` 使用同一份受控清单，但将安装探测和执行注册分开。`packages/protocol` 增加可选、带版本的清单快照，独立于 `heartbeat.runtimes`。服务端按当前在线会话提供给计算机详情页，不为发现清单建表。 | 已安装、未安装、未上报能区分；仅被发现的程序绝不出现在任务选择器。 |
| M2：Copilot 能接单 | `apps/artood` 先实现一个窄适配器：`copilot --acp --stdio`，一条 Run 一个进程和会话。实现握手、一次输入、流式文本、错误、取消及关闭，复用现有 Run 生命周期。接上服务端派单和 Web 手动入口。 | 经授权的真实账号完成任务、能停、能再接下一单；没有原生关闭证据则不开放。此时才可发布单节点试用版。 |
| M3：验证第二款 | 用 `agy acp` 走相同套件。只有两个真实入口确有相同逻辑时才抽共享层；不先建插件市场或重写既有适配器。 | 独立记录 `agy` 的验收版本、结果和阻断原因；不通过只保留发现。 |

### 编码前锁定的四条契约

**1. 手动派单是正向许可，不是 capabilities 匹配。** 对本切片的新运行时，服务端在候选筛选、最终派发两处使用同一判定：由当前用户明确手动指定这个实例，服务端确认任务来源和内容为本切片的单轮纯文本任务，且当前在线节点会话上报了新鲜、可用的对应执行资格。`required_capabilities: []`、手动但没指定实例、运行时行缺失或仅为 `detected` 都不能代替这些条件。即使指定了实例，`mode: auto`、GoalRunner 来源、`branchBacked`、`product_development`、要求产物或交接的任务都拒绝。任务标题、模型文本或请求自报的“纯文本”标签不能证明来源。节点收到 `run.start` 时再次校验本机开关、入口、版本、受限配置和任务契约；任何缺失或不一致，在启动进程前拒绝。旧实例的空记录回退保持原样。

**2. 不改变已配对节点的本地文件格式。** `validateConnection()` 在读、写 `connection.dat` 时都校验 v1 的 `runtimes`；该数组还用于生成 `ARTOO_RUNTIMES`。整个 MVP 都不把新名字写入这个数组，也不把发现对象整体展开保存：配对与重新启动时只投影原有字段。发现清单只在内存重建；M2 的本机启用策略独立于连接文件，资格在当前会话绑定到经过验证的入口。验收时用同一份配对数据走“旧版配对 → 新版发现/启用 → 旧版读取并启动”，不能要求重配，也不能把新 CLI 带入旧运行时列表。

**3. ACP 拒绝回调不等于 CLI 无工具。** 客户端不提供文件或终端能力，不注入 MCP；对 `session/request_permission` 一律不授予。节点只采用目标 CLI 版本已证实有效的工具禁用配置，不假定交互模式的参数在 ACP 模式也生效。使用独立空临时 `cwd`、显式 `env` 白名单和私有配置，不继承用户插件、节点控制凭据或宿主环境。**空目录不是文件访问隔离**：资格测试使用无敏感数据的专用账号/目录和合成标记，分别验证内置读文件（含 `cwd` 外）、读取非白名单环境、写入和启动终端均被阻止。保留有效配置、节点侧可观察的访问/进程证据及能验证观察手段的对照结果；只看到模型拒答、没收到权限回调或文件没变，都不能证明未读取。不能约束或观察内置访问时，该版本仅展示发现结果，不开放执行。

**4. T17 不改变主线交付条件。** M1 使用现有 `node.heartbeat` 上独立、可选、带版本的发现快照，不扩写既有必需的 `runtimes` 完整快照语义；省略表示未上报，不是空清单。M2 的执行能力另行协商，默认关闭：新节点连旧服务端不开放新适配器，旧节点连新服务端不获得执行资格。新适配器独立接线，不改 `runtimes.ts` 中 Codex/Claude 的注册行为或 `createProcessAdapter` 主路径。T17 的试用安排在 Web + Windows 多机协作核心闭环之后；可独立开发和回归，不设为核心闭环或 T19 的前置条件。

节点继续负责整体超时、输出限额、子进程树和实际关闭；取消回应、输出 EOF 或模型最后一条消息都不算进程已停。关闭未确认时保留占用，不自动重试。普通任务回答不能生成 `run.verification`、评审批准或发布凭据。

## 四、验收和回退

| 验收层 | 必须看到的结果 |
| --- | --- |
| 发现与兼容（受控） | 覆盖已安装/缺失、同名伪入口、不可用 shim、卸载、版本替换、新旧节点/服务端混用。即使直接调用派单 API，也启动不了未合格的 CLI；原 Codex/Claude 回归通过。 |
| 派单负例（受控） | 用 `required_capabilities: []` 同时覆盖 auto、未指定实例的 manual、GoalRunner、分支、产品和交接任务；分别验证候选被排除、派发前资格失效时不发命令，以及节点独立拒绝不合格的 `run.start`。保留一条合格手动任务的正例，对照旧实例空记录回退仍有效。 |
| 交互与权限（受控） | Web 能看到首段输出和正常结束；明确区分未登录、额度不足、协议错误、超时，无法区分时显示未知。拒绝读取或修改项目、运行终端及加载未允许的工具。迟到输出不能把已停止的 Run 改回成功。 |
| 真机（逐 Provider） | 在记录版本的 Windows 节点、经授权账号上，跑一条含随机标记的文本任务、一次流式中途 Stop，再启动一条新任务。核对父子进程实际关闭、项目目录无改动、槽位在确认关闭后才可复用。没有真实凭据或关闭证据只记阻断；fixture 不替代此项。 |
| 灰度与回退 | 先部署兼容服务端，再单节点显式启用。认证失效、CLI 更新、同版本入口或受限配置被替换，撤销资格并要求重验。关闭单个 Provider 开关即停止接新单；在途 Run 正常结束或走原停止流程，不删除历史、不影响 Codex/Claude。 |

实施时运行仓库要求的 typecheck、build、单元和 Web E2E；分别记录受控测试、真实 Provider 和灰度结果。此切片不覆盖原 T17 的旧 Gemini CLI、通用多轮输入，也不替代 T19 的综合验收。
